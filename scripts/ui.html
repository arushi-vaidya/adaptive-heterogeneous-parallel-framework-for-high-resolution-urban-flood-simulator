THE COMPUTATIONAL CHALLENGE

Flood simulation is a computational problem.

More detail means more work. The challenge is spending that work where water dynamics make it matter.

FRAMEWORK CONTRIBUTIONS

What makes this different?

A focused implementation of adaptive flood computation, with numerical evidence surfaced alongside runtime results.

01 — ADAPTIVE SPATIAL RESOLUTION⌗

Spend resolution where it matters

Computational resolution is concentrated around dynamically important regions rather than uniformly increasing the entire grid.

02 — HETEROGENEOUS EXECUTION⫶

One physics, multiple backends

The same physics-based solver is evaluated across Serial, OpenMP and MPI execution paths.

03 — DYNAMIC MPI BALANCING⇄

Redistribute uneven work

Adaptive refinement can create uneven workloads, so MPI ownership is dynamically redistributed when imbalance is significant.

04 — CONSERVATIVE COUPLING∑

Preserve conservation across levels

Coarse/fine interfaces and adaptive regridding are instrumented with conservation residuals in the solver and benchmarks.

IMPLEMENTATION OVERVIEW

From terrain to measured output.

Architecture reflects the implemented solver pathways and output records.

01

INPUT / SCENARIO

Terrain and rainfall inputs · built-in dam-break and rainfall/drainage scenarios.

02

GRID / STATE

Uniform Cartesian grid or adaptive patch hierarchy with conserved water state.

03

FINITE-VOLUME SOLVER

Shallow-water equations · hydrostatic reconstruction · Rusanov flux · CFL timestep.

04

ADAPTIVITY

Patch refinement and coarsening · coarse/fine interfaces · regridding diagnostics.

05

PARALLEL EXECUTION

Serial reference · OpenMP shared-memory execution · MPI distributed-memory execution where available.

06

DYNAMIC LOAD BALANCING

Weighted MPI patch ownership · measured workload imbalance · patch and cell migration.

07

OUTPUT / EVIDENCE

Generated depth and refinement maps · benchmark timing · conservation residuals · validation tests.
